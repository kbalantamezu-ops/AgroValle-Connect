# Retrospectiva Sprint 2 — Start-Stop-Continue

## Start (Empezar a hacer)

- Probar los flujos completos desde la interfaz web antes de cerrar cada historia.
- Mantener el tablero y las issues de GitHub sincronizados con el código.
- Documentar las decisiones de arquitectura y los endpoints en el mismo sprint.

## Stop (Dejar de hacer)

- Acumular ramas de funcionalidad después de fusionarlas.
- Resolver conflictos de merge sin ejecutar `./mvnw clean verify` antes del push.
- Dejar la documentación de sprint para el final del proyecto.

## Continue (Seguir haciendo)

- Usar Conventional Commits y ramas cortas por historia.
- Ejecutar Checkstyle, pruebas y cobertura en cada cambio.
- Mantener la cobertura por encima del 60% y el pipeline en verde.
- Revisar los endpoints con pruebas de integración.
